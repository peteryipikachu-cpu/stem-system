本版本围绕「Qwen 模型深度推理与思考预算调优」「L0 格式校验算法防误伤加固」「项目管理 UI 布局重构与创建时间透出」「题目编辑新版本状态重置与交互优化」以及「项目数据量折算与 Token 成本分析」五大核心方向展开优化与交付。

## ⚡ Qwen 模型深度推理与思考预算调优

- **下发 `thinking_budget: 32768` 思考预算**：
  - 在 Worker 构造 Qwen 系列模型（`qwen3.7-plus``qwen3.7-max` 等）请求 Payload 时，显式配置 **`thinking_budget: 32768`** 思考上限参数。
  - 给 Qwen 提供了全额的 **32,768 Tokens**（约 2.5~3 万字）深度解题推导空间，完全满足极高难度的竞赛级 STEM 题目推导需求。
- **彻底消除 `empty_completion` 与 `invalid_answer_format` 截断故障**：
  - 从源头解决了 Qwen 模型在无约束时无休止思考暴增至 10~20 万 Tokens 导致的“思考完正文为空”（`empty_completion`）与“未吐完 `<final>` 闭合标签被腰斩”（`invalid_answer_format`）问题。
  - 上游抓包实测确认：Qwen API 在 `thinking_budget: 32768` 与 `max_tokens` 在 `[1, 131072]` 范围内时，100% 成功返回 HTTP 200 OK，跑数稳定性显著提升。

## 🛡️ L0 格式校验算法防误伤加固

- **公式段内连不等式防误伤隔离**：
  - 修复 `md-inline-html` 规则在检测 HTML 标签时误把数学公式段中的连不等式（如 `$0<c<\frac12$` 中的 `<c<\`）识别为 HTML 标签（`<\s*/?[A-Za-z][^>]*>`）的缺陷。
  - 在扫描 `md-inline-html` 与 `md-link-unclosed` 规则前，**先屏蔽 `$ ... $` / `\[ ... \]` / `\( ... \)` 数学公式段**内的文本，确保包含连不等式的题目 100% 顺利通过 L0 格式校验。

## 🎨 项目管理 UI 布局重构与创建时间透出

- **透出创建时间与创建人**：
  - 在“我的项目”管理卡片中增加了**创建时间**（格式化为 `YYYY-MM-DD HH:mm`）与创建人的透出，例如 `创建：admin · 2026-08-05 10:36`。
- **项目卡片底部重构为上下分行布局**：
  - 针对原左右 Flex 布局在较窄屏幕或项目成员描述较长时容易导致挤压重叠的体验痛点，将卡片底部重构为**上下两行垂直 Stack 结构**：
    - **第一行**：`<TeamOutlined />` 成员分布（项目管理员数、普通用户数）；
    - **第二行**：`<ClockCircleOutlined />` 创建人与创建时间；
  - 视觉效果更加舒展清爽，适应各种屏幕尺寸。

## 📜 题目编辑新版本状态重置与交互优化

- **保存新版本时主表状态优雅重置**：
  - 编辑题目保存生成新版本（`PUT /api/questions/{id}`）时，主表上的旧定级结果（`difficulty_status = "pending"`、`difficulty_level = None`、`difficulty_run_id = None`）自动清空重置，确保新版本物理状态恢复为 `待检测 / 未评级`，彻底消除旧版本定级结果残留在主表上的混淆假象。
- **编辑“修改说明”强校验必填**：
  - 前后端同步将 `changeNote` 设为强校验必填项，编辑题目保存时必须填写修改说明，防止留下无说明空白版本。
- **历史版本展卡多维判定标识**：
  - 题目列表页展开行的“历史版本”表格大幅丰富：新增透出 **“定级结果”**（如 `L3`）、**“是否合格”**（如 `合格`/`不合格`）以及 **“AI合成检测”**（如 `疑似合成`/`原创`）多维判定标签，历史版本质检轨迹一目了然。
- **跨项目切换页码自动归位**：
  - 修复从题目较多的项目切换到新项目时页码残留旧页数的问题，实现切换项目时页码自动精准重置归位至 `第 1 页`（`setPage(1)`）。

## 📊 项目数据量折算与 Token 成本分析

- **精细化题目折算规则与脚本交付**：
  - 提供了项目题目量精细折算能力：
    1. **未质检即修改**：算 1 道（不加算）；
    2. **质检合格后修改**：算 1 道（不加算）；
    3. **质检未合格而后修改**：每次 +1 折算（即未合格而修改累算 2 道）。
- **Token 费用账单分析**：
  - 提供了针对指定项目（如 `projectId = 34`）全量模型调用的 Token 消耗（Input/Output/Reasoning）与折合人民币费用账单的分类统计工具 [scratch/summary_report_short.py](file:///Users/pikachu/.gemini/antigravity/brain/5fd58aef-534c-441a-b02d-5d41b9eeb547/scratch/summary_report_short.py)。
